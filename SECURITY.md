# Security reports

Do not include API keys, Twitch tokens, notes databases, private transcripts or credential-store exports in public issues.

Report sensitive vulnerabilities privately through the repository's GitHub security advisory channel when private reporting is enabled. If that channel is unavailable, open a public issue asking the maintainers for a private contact **without disclosing exploit details or user data**. Maintainers should enable private vulnerability reporting before a broad release.

Include the Rocky version/commit, operating system, affected feature and a reproduction using synthetic data. The project is in alpha; there is no guaranteed response time or supported stable-version window yet.

See [data handling](docs/PRIVACY.md). Signing and live validation remain release checks, not claims inferred from unit tests.
